~/projects/video-pipeline

=========================

## pitch

Search, download and edit video from the terminal. Claude Code makes the editorial calls: which candidate to take, where each shot starts and ends, what gets cut. yt-dlp and ffmpeg do the work.

## search

Search uses yt-dlp's built-in YouTube search. It lists candidates without downloading anything.

yt-dlp "ytsearchN:<query>" --flat-playlist --print "<duration> | <channel> | <title> | https://youtu.be/<id>"

Claude then checks candidates. It downloads a short section or a few sample frames to see the content, and runs yt-dlp -F <url> to find the maximum height before committing to the winner.

## download

  • ytdl <url> saves to ~/Downloads/ with a format that prefers an H.264 MP4 stream. An ffprobe check reads the video codec. H.264 is kept as is. Anything else, such as AV1, is transcoded with libx264, aac and -movflags +faststart to <title> (QT).mp4 so it plays in QuickTime.
  • ytdla and the ytmp3 alias save audio only, as MP3, to ~/Downloads/.
  • Editing downloads use -S "res:1080,vcodec:h264,acodec:aac" -f "bv*+ba/b" --merge-output-format mp4 --no-playlist, sometimes res:2160.
  • Long videos are downloaded by section only, such as a 90 second window, to avoid multi-hour files.
  • Slow or stalled downloads get -N 16 for parallel fragments.

Quote the URL when it contains &. The shell functions live in ~/.zshrc.

## edit

All editing is ffmpeg. Claude views images, so it picks shots by looking at them rather than by reading timestamps.

  1. ffprobe for duration, fps and resolution.
  2. Contact sheets: fps, scale and tile filters combine many frames into one image. Finer 4 to 8 fps strips cover candidate moments.
  3. Scene-cut detection lists cut timecodes, so cuts land on shot boundaries and not mid-shot.
  4. Each shot is trimmed, scaled and padded to 1920x1080, given a 40 to 60 ms audio fade in and out, and re-encoded at crf 18 with aac at 48 kHz.
  5. Shots are joined with a list.txt concat file.
  6. Seams are checked on a contact sheet or on single frames.
  7. Index files record each named clip with its source and in/out points, next to a tiled overview image.
ffmpeg -i in.mp4 -vf "select='gt(scene,0.30)',metadata=print:file=scenes.txt" -f null -
ffmpeg -ss <start> -t <dur> -i in.mp4 -vf "scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,setsar=1,format=yuv420p" -c:v libx264 -crf 18 -c:a aac -ar 48000 shot_014.mp4
ffmpeg -f concat -safe 0 -i list.txt -c copy out.mp4

## what it made

  • An action-trailer re-edit from an EDL, iterated v1 to v3 after feedback on mid-shot cuts and pacing.
  • Punch-up shots from extra searched trailers: explosions, gunfights, fight scenes and chases.
  • Named time ranges cut from several trailers, plus a scene found by scanning an 11-minute video.
  • A library of 73+ named action selects.
  • A 69-shot, ~59 s reel, built with a build script kept in a session scratch folder.
  • A 32-clip B-roll set for a pitch reel. Weak shots were swapped out, and one static shot was generated with ffmpeg.
  • A find-similar search for a shorter multi-person clip in the same layout as a reference.

## gotchas

  • AV1 does not play in QuickTime. Prefer H.264, and transcode only as a fallback.
  • Low-resolution sources were flagged after the fact. Check the resolution of every clip, and replace low-res sources with 1080p.
  • Stalled downloads (2026-09-10) were diagnosed with a yt-dlp version check and test fetches. The fix was -N 16, and --extractor-args "youtube:player_client=web_safari,tv" was also tried.
  • Cuts landed mid-shot until scene detection was added.
  • An EDL's file names were wrong. They were checked against a second EDL before use.
  • This ffmpeg build lacks the drawtext filter, so contact sheets have no burned-in timecodes. Position in the grid gives the time.
